# credit-os-connected (Claude sessions, local and cloud)

@AGENTS.md

`AGENTS.md` (imported above) holds the project rules. This file only fixes how sessions are organised.

- Non-trivial work runs as a coordinator: it plans, writes each step's brief, runs `/advisor` on the plan once before the first dispatch, then dispatches `mx-*` agents (`.claude/agents/`). The coordinator writes no code.
- Briefs and `/advisor` critiques live in `.superpowers/sdd/<plan>/` (gitignored, never committed, so they add nothing to the repo). A local sub-session gets the brief's absolute path in the coordinator's worktree; a cloud sub-session gets the brief in its start prompt.
- Models and effort: `mx-scaffold` (Sonnet, low) mechanical work with a full spec; `mx-feature` (Sonnet, medium) everything else that writes code; `mx-precise` (Opus, medium) task review; `mx-adversary` (Opus, xhigh) money, ordering/concurrency and security code; `mx-invariants` (Opus, high) ordering and state-transition review when correctness depends on interleaving; `mx-architect` (Fable, high) the pre-merge review and any `mx-adversary` audit that was refused; `mx-advisor` (Fable, high) read-only plan critique. A sub-session runs on its coordinator's model.
- Every brief and reviewer prompt states: no stub or fake value standing in for real behaviour; no catch-all hiding a failure unless documented and logged; the task's answer key, which the implementer does not edit. Every report ends with a `Not verified:` line. A code fix starts with a test that fails for the reported cause.
- Fix rounds: at most two Sonnet rounds per task, and only a round fixing a High or Medium finding counts. A third goes to `mx-autonomous` (root cause and smallest fix plan) then a fresh `mx-feature`. No fourth: take the open findings to the owner.
- A plan step is its own sub-session only if it ends in its own PR, shares no file with another step, and neither needs nor supplies another step's result. Only the coordinator writes shared records (`VERIFICATION.md`, rulings, the ledger), at merge; a sub-session returns its lines in its report.
- Finish, in order: quality gate; the coordinator runs `confidence-review`, `rewrite-tournament` and `/sweep refactoring discover changed-update` on the branch diff, with fixes going to `mx-feature`; the pre-merge review (`mx-architect` on the PR diff, running `adversarial-reviewer` where the skill exists, else reviewing for correctness, security and requirement gaps with the CRITICAL/WARNING/NOTE to High/Medium/Low map). Where a skill is absent (cloud), skip that step and name it in the PR body's `Not verified:` line; then tell the user to type `/ship`. `/ship`'s own review adds no round: act only on a High or Medium finding it raises. Merges happen on the owner's instruction.
- Docs/config-only PRs skip the confidence-review, tournament, sweep and pre-merge steps; one `mx-feature` review is their review, and `/ship`'s review adds no round there either.
- `.claude/agents/` and `.claude/commands/advisor.md` are copies of `~/.claude/`. Whoever edits an original refreshes the copy. Check (exit 0 means in sync): `diff -rq -x 'impeccable-*' -x 'opus55-*' ~/.claude/agents .claude/agents && diff -q ~/.claude/commands/advisor.md .claude/commands/advisor.md`
- Agent files mention this Mac's harness (Monitor, rtk, no `timeout` binary). In cloud sessions those lines do not apply and `timeout 300` works as `AGENTS.md` says.
- Cloud sessions load `.claude/agents/` (confirmed 2026-11-25). Not verified: cloud loading of `.claude/commands/` and of this file.
- Design work (owner, 2026-11-25): use, adapt or repurpose components, templates, blocks and assets from shadcnstudio.com, shadcnuikit.com, untitledui.com/react/components, shadcnblocks.com, pro.reactbits.dev/docs/introduction, pro.reactbits.dev/docs/components and shaders.com/docs/components, plus the sources in `~/.claude/CLAUDE.md` §6 (reactbits.dev, flowbite-react, uiverse loaders, hyperui, preline, ant.design grid). Read the live page before using one; desktop only, blue accent (`DESIGN.md`).
