## Cause and repair

The scheduler stores runs under a timestamp folder ID. The existing launcher
creates its analytical ID from issuer, as-of date, pathway and configuration even
when `--out` names the scheduler folder. The display adapter compared the two
different IDs and returned unknown metadata after an ordinary synthetic run had
completed and exported all fourteen accepted module responses.

`react_frontend/run_metadata.py::_workflow` now derives the expected analytical ID
from the scheduler record's existing identity and `runs.config_for(model, effort)`.
Issuer ID/name, date and pathway must still match exactly. The workflow must also
match the complete existing engine `identity.json.run` pin, including additional
fields such as case kind and requested modules. A missing, linked or different
identity pin leaves the optional metadata unknown.

No event-state, selection, bounded-reader, request fingerprint, instruction/source,
upstream, response hash, accepted-review or retained-response validation changed.
The reader performs one extra bounded local identity read. No analytical method,
prompt, calculation, module passage, proof launcher or canned handoff was edited.
No provider, paid execution, real Submit, seat check, Teams or application-network
call occurred; the existing synthetic launcher replaces the adapter and refuses
outbound socket operations.

## Confidence, simplest alternative and fidelity

The named confidence-review/rewrite-tournament skills are unavailable in the
catalogue. Direct doubt tracing and post-edit simplification were used:

- **Could an arbitrary workflow ID now pass?** The expected ID is derived from
  the saved scheduler identity and existing launch mapping; an actual-artifact
  mutation back to the scheduler folder ID is refused even when its engine pin
  is changed to agree. All five identity fields and both differing model/effort

- **Could the workflow disagree with the engine's current identity?** Exact full

  request, review, ambiguity, later-start/rejection, link and read-budget guards

  verifies both pending and accepted metadata states.

engine's run identity would be broader or weaker alternatives. The retained
design changes only the presentation adapter's ID expectation and checks the
existing engine pin. It reuses the current launch configuration mapping and adds
no abstraction, compatibility shim or second orchestration path.
