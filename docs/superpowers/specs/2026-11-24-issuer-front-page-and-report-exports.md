# Issuer front page and report exports

## Outcome

A portfolio manager opening an issuer from the Library lands on a decision-ready credit summary. In about a minute they can state the credit view, the main risk, what would change the view, and the instrument preference when the run reached one. The same selected run can be saved as a Credit Snapshot PDF or, for a purpose-specific run, as its matching specialist PDF.

The Paysafe screenshots in `Desktop/Enterprise data/credit snapshot` inform the layout and content, as do the [inherited Deploy Workflow report compositions](../../../src/deploy_vii/report_view.py). The screenshots supply no figures for current reports. The [reader ruling](../../rulings/2026-11-11-reader-and-issuer-report.md) and [project instructions](../../../AGENTS.md) govern analytical ownership and trace.

## Entry and run selection

- The default issuer-card action opens Overview for the newest eligible Full or Deep assessment in the admitted Library. Eligibility requires confirmed standard pathway scope and a designated, assessable, reader-visible committee or fundamental bottom line. Confirm scope from the frozen requested modules and verified delivery scope against the preset recorded for that run. A requested subset, comparison-only run or incomplete delivery is partial even if it has a usable bottom line. A missing optional comparison or a disclosed analytical gap does not make an otherwise verified preset partial. Keep legacy runs whose scope cannot be established available in history and label their scope as unverified.
- Rank eligible runs by valid analysis as-of date, newest first, with unknown dates after dated entries. Within a date, use a verified publication timestamp only when every tied candidate has one. Otherwise use stable folder ordering for the whole tie. That ordering resolves navigation only and makes no claim about which publication was newer. Use the Library's canonical issuer identity. When identity is absent, treat the entry as its own issuer.
- Show a newer published earnings update, specialist report, or partial assessment as a link with its own date and pathway. For the same as-of date, call another report newer only when verified publication times establish the order. Otherwise list it as another report for that date.
- If there is no eligible Full or Deep assessment, open the latest published Lite with verified standard Lite scope and a reader-visible credit view. Otherwise open the latest admitted report, show its actual scope, and say when a verified issuer assessment is unavailable. Explicit history selections and links always open the named run. Keep history and pathway filtering available, including direct access to specialist runs.
- Display issuer name, ticker when available, assessment as-of date, financial period and pathway. Show separate market or ratings observation dates wherever material. An in-flight run remains in Run activity. Older-format or preview material carries its existing qualification.

## Front page composition

Use the first desktop screen and first PDF page for the same compact issuer brief. The Paysafe reference puts credit strengths and weaknesses beside a financial, balance-sheet and credit-metric grid. Its relative-value sheet puts rank, size, maturity and price on the instrument's own row. Carry over that hierarchy and scanability. Put the full peer grid and period schedules in the relevant exhibits.

| Order | Content | Source and display rule |
| --- | --- | --- |
| 1 | Issuer profile | Show issuer, ticker, sector and country, with a one-line description of the business from the designated facts. Include ownership or sponsor and dated issuer-level ratings and outlooks when established. Include a material segment or customer concentration only when it helps explain the view. Keep facility ratings attached to their facilities. |
| 2 | Credit view | Lead with the owning module's shortest complete, reader-visible conclusion. Overview and PDF use the same module, output ID, hash and source line. If the owner supplied a separate compact summary, retain its full credit view in the exhibits and on the Library card at the full view's published coordinates. Follow with the support, risk and change triggers the owner wrote for the reader. A specialist run leads with its purpose finding. |
| 3 | Capital structure and liquidity | Give the debt stack a first-page table. Use material facilities and debt by rank, with borrower or collateral perimeter when it matters, outstanding principal, denomination, coupon or margin and maturity where supported. Keep undrawn commitments separate from funded debt and principal separate from carrying value. State the relevant near-term maturity or liquidity restriction beside the table. Show a dated price, yield or spread only for an exactly matched instrument with a verified quote basis. |
| 4 | Credit metrics | Prefer one aligned grid over separate tiles. Use the latest and a comparable prior period when both exist. Show available revenue, EBITDA, FCF, net leverage, interest cover and liquidity. Share period and currency labels where they genuinely match. Keep basis differences that change interpretation beside the figures. |
| 5 | Decision visuals | Use one lead chart when it advances the credit view. Prefer the maturity wall when refinancing drives the view, or a leverage, cash flow or liquidity trend when it better explains the risk. Use a second chart only when it answers a separate material question. Label actual, pro forma and projected observations distinctly. |

Place the credit view and compact metrics beside the capital structure on wide screens and landscape paper. Use plain credit terminology. State the one or two qualifications that change a decision. Use a concise inline missing state for a material gap. Move repeated periods, generic availability messages, figure observations, longer limitations, module bottom lines and supporting charts below the first screen or onto continuation pages. Preserve material contrary evidence and the existing module, Changes and Evidence destinations. Keep one trace control per narrative paragraph, row or figure. Delivery selects authored passages and source-backed rows. Any missing short conclusion, issuer fact or normalized debt observation belongs to the owning module for repair.

Use the designated Relative Value output for instrument preference and the designated Committee output for action or sizing. Before displaying an actionable field, require an explicit owner judgment, assessable published status, and verified publication treatment bound to the same designated output ID and hash. A recorded hold at the applicable run, module, instrument or portfolio scope overrides positive wording for that same scope. An affirmatively accepted call with limitations can appear with those limitations. Where clearance cannot be established, withhold the call, including in summary prose, captions and tables that repeat it. Use the next eligible factual reader passage and display the recorded restriction or an availability message. An issuer credit judgment can still be shown independently.

### Visual fidelity

- Graph only supported values from the selected run. A Model chart requires an accepted delivery owned by that issuer and run. A run listed as one of a Model's input sources does not own the delivery. If there are multiple owned deliveries, use the explicitly designated accepted one or show a gap. Label amount, currency, scale, period, scenario and basis as applicable. Never treat missing as zero, join an unrelated period or interpolate across an unsupported interval. Show known single-period data as a point or actual-value display. A missing key chart gets its reason and, when usable, a table of available observations.
- Give each chart a concise published takeaway when the owner supplied one. Otherwise use a descriptive caption that identifies the plotted series or the gap. Reuse exact-value table data where available. Keep market observations separated by compatible quote measure, instrument and date. A loan's discount margin and a bond's spread or yield need their own scales.
- Use the adopted chart palette, direct labels, line styles and markers so the chart works in grayscale. Distinguish historical, pro forma and forecast observations in both formats. Preserve trace and all existing chart qualifications.

## PDF deliverables

| PDF | Eligible run | First-page decision and lead visuals |
| --- | --- | --- |
| Credit Snapshot | Lite, Full or Deep with a published credit view | Compact issuer brief, capital structure, key credit metrics and the lead decision visual. Use the actual tier in the masthead. |
| Earnings Update | Earnings Update | Latest results and change in credit implications. Show comparable quarterly series or prior/current comparisons. Draw a variance bridge only from a published, reconciled bridge. |
| Relative Value | Relative Value | Preferred instrument and entry level if published. Show dated yield or spread against maturity and a security table. |
| Covenant & Refinancing Brief | Covenant & Refinancing | Headroom, upcoming funding need and lender implications. Show maturity concentrations, covenant headroom or a published liquidity bridge. |
| Distressed & Restructuring Brief | Distressed & Restructuring | Distress assessment, runway, likely path and recovery by class where supported. Show a runway and published recovery ranges or value-allocation chart. |
| Portfolio Decision | Portfolio Decision | Proposed action and size, committee challenge, portfolio fit and binding limits. Show corroborated exposure and limit headroom. Show pre/post comparisons only when both bases are supported. |

Eligibility also requires that the format is qualified for release and the selected run has a supported substantive finding for that format. The PDF retains the same partial or verified scope as the selected run. A held recommendation permits export of an otherwise supported report with the restriction and reason prominent. The relevant report action explains unavailability when no usable finding can be printed. Other formats do not appear as choices for the run. A past Short Credit Snapshot remains readable under its historical scope. It does not qualify as a current Credit Snapshot export.

### Preview and print

- Put **Export PDF** beside the run selector in the report reader. Open a same-run, in-app print preview with the format, scope and report qualification visible. **Print / Save PDF** invokes the browser dialog after the print layout is ready. Browser cancellation returns control to the preview. Close returns to the same report tab and run. The preview retains any authorized preview qualification in the print itself.
- Use the same selected passages, figures, and qualifications on screen and in the PDF. Assemble with React from the existing admitted publication. Print text and vector chart marks where supported by existing components. Give the export its own print layout within the native reader. PDF export has no provider calls, separate HTML deliverable, workbook, raw-file bundle or server-side document job.
- Fit the compact Snapshot brief on the first A4 landscape page. Put full schedules, longer passages and exact-value chart exhibits on continuation pages with repeated identity and scope. Longer reports lead with the decision and main chart and paginate their supporting tables. Use at least 10 pt for body text and 9 pt for labels and tables in the target layout. Keep charts with captions, repeat table headers, and wrap long cells. Carry issuer, report name, pathway, as-of and applicable restrictions in the document. Use CSS page numbering only if verified in the supported print browser.
- Give the report a compact Credit OS masthead and approved mark, with a white paper background, the theme's darkest brand tone for text and rules, and its brand tone for emphasis (`--color-brand-950` and `--color-brand-600`; navy `#000533` and ultramarine `#001AFF` until the redesign of 2026-11-25, teal since). Use the theme's display and body faces with tabular numerals. The [design authority](../../../DESIGN.md) and the [token register](../../design/design-system.md) govern.
- Link back to the exact run inside the app. A PDF can contain a clickable report link only if the application supplies a recipient-usable approved address. The local edition's print layout and document title carry human-readable identity without internal paths or IDs. Browser-added headers and footers are controlled by the user and can include the local report URL. The preview tells the user to turn them off before saving a PDF for sharing. This release does not establish remote sharing.

## Publication and acceptance

CP-OS and delivery publish the selected run as today. Overview and export consume the same designated, admitted publication. Export is reader presentation. It neither changes workflow completion nor opens a second analytical execution. Published Markdown, HTML Model, chart and calculation artifacts, and existing Evidence downloads retain their roles. Client composition uses safe existing rendering. The print document contains reader-visible selections only, including for portfolios and preview scope.

Acceptance requires a retained assessment comparison with its actual handoffs and a readable saved PDF. Check judgment, contrary evidence, action qualifications, selected issuer and run, periods, currency and units, exact values, zero versus missing, series and scenario labels, conditions and evidence links. Cover a newer specialist run alongside an older assessment, explicit older-run selection, a held recommendation, a missing chart, long content and print readiness. Check each specialist format against a corresponding published case before calling that format qualified. Label synthetic, retained and preview evidence with its actual scope. Record presentation fidelity in [VERIFICATION.md](../../../VERIFICATION.md).
